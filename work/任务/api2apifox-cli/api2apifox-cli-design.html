api2apifox 独立 CLI 技术设计

将现有 VS Code 扩展的 Java 静态解析、OpenAPI 构建和 Apifox 同步能力抽成共享核心，并以 @duyiliu/api2apifox 独立发布。

命令：api2apifoxNode.js ≥ 202026-09-20主要受众：AI / CI / 开发者

核心结论：采用“同仓库双产品、共享核心、独立发布”。CLI 提供 scan、export、sync、config 四个命令，以稳定 JSON 信封、明确退出码和显式写入确认服务 AI Agent。

设计边界

本方案只设计，不修改现有业务代码。VS Code 的命令、配置键、SecretStorage 和 Marketplace 发布链保持兼容；CLI 不复制第二套解析器。

3. CLI 命令

scan

扫描源码并输出接口摘要，不写文件、不访问 Apifox。

api2apifox scan --project . --format json

export

生成 OpenAPI 文件。覆盖已有文件必须显式 --force。

api2apifox export --project . \
  --output openapi.gen.json

sync

预检后同步。非 TTY 必须传 --yes；--dry-run 不写远端。

api2apifox sync --project . \
  --yes --format json

config

输出最终配置与字段来源，Token 只显示是否存在。

api2apifox config --project . \
  --format json

精确范围

--file 可重复--endpoint "METHOD PATH" 可重复全量类型上下文

单文件或单接口同步仍扫描项目全量源码用于 DTO 解析，只筛选最终输出，保持与 VS Code 当前行为一致。

4. 配置模型

优先级：CLI 参数 > 环境变量 > .api2apifox.json > 内置默认值。首版不静默读取 VS Code settings。

{
  "$schema": "https://unpkg.com/@duyiliu/api2apifox/schema/config.schema.json",
  "projectId": 123456,
  "apiBaseUrl": "https://api.apifox.com",
  "include": ["**/src/main/java/**/*.java"],
  "exclude": ["**/target/**", "**/build/**", "**/src/test/**", "**/.*/**"],
  "endpointConflictBehavior": "OVERWRITE_EXISTING",
  "schemaConflictBehavior": "OVERWRITE_EXISTING",
  "pageTypeStyle": "mybatis-plus",
  "folderNameSource": "tag",
  "helperProperties": { "enabled": true, "enumFieldDoc": false }

5. AI 输出协议

--format json 时，stdout 只能输出一个最终 JSON 对象；进度与诊断写 stderr，禁止颜色和普通日志污染。

{
  "schemaVersion": 1,
  "ok": true,
  "command": "sync",
  "version": "0.1.0",
  "durationMs": 482,
  "result": {
    "dryRun": false,
    "target": { "projectId": 123456 },
    "scope": { "type": "workspace", "endpointCount": 42 },
    "counters": {
      "endpointCreated": 2,
      "endpointUpdated": 40,
      "endpointFailed": 0
    },
    "errors": []
  },
  "warnings": []
}

失败同样输出稳定信封，AI 优先读取 error.code，外层脚本可按退出码快速分支。

退出码

码含义典型错误
0成功OK
2参数/配置错误CONFIG_INVALID
3没有 Java 文件或目标接口NO_ENDPOINT_MATCHED
4鉴权/权限失败APIFOX_AUTH_FAILED
5网络/超时REQUEST_TIMEOUT
6导入部分失败IMPORT_PARTIAL_FAILURE
7I/O 或内部错误INTERNAL_ERROR
130取消CANCELLED

6. 安全策略

  • scan、config、export 默认只读。
  • sync --dry-run 不调用 Apifox 写接口。
  • 实际同步必须交互确认或显式 --yes。
  • 非 TTY 且无 --yes 时立即返回，不允许挂起。
  • 配置文件禁止 token 字段；Token 不进入 stdout、错误栈或日志。
  • 默认不删除 Apifox 中未匹配资源，首版不暴露删除开关。
  • 接收 SIGINT/SIGTERM，取消返回 130；文件导出采用临时文件 + rename。

8. 实施顺序

  1. 抽取共享核心：扫描、Maven 依赖、规则加载、分析和同步服务。
  2. VS Code 回接共享核心：现有命令和 OpenAPI 输出保持不变。
  3. 实现 CLI MVP：四个命令、配置、JSON、退出码、确认和取消。
  4. 验证：子进程测试、mock Apifox、跨平台路径、VS Code/CLI OpenAPI 一致性。
  5. 发布：独立 npm 工作流，发布 0.1.0。

9. 验收重点

场景决定性标准
JSON 可消费性stdout 恰好一个 JSON 根对象，无颜色或进度污染
行为一致性相同 fixture 下 CLI 与 VS Code 生成的 OpenAPI 深度相等
非交互安全sync 无 --yes 时快速失败，不等待 stdin
事实边界不虚构 Apifox 未返回的逐接口同步状态
凭据安全任何成功/失败输出均不包含 Token
跨平台Windows、Linux 路径和 glob 结果一致
发布包npm tarball 仅含白名单，安装后 api2apifox 可执行
推荐下一步

从“抽取 ProjectAnalyzer/ProjectScanner/SyncService，并让 VS Code 先回接”开始，而不是先写 CLI 参数层。只有核心编排真正无 VS Code 依赖，CLI 才不会成为第二套实现。
