feat(sync): 同步报告输出接口级 Apifox 链接与 mock 地址

Issue #40：把同步结果从"数量统计"升级为可直接消费的接口索引。

- importOpenapi 宽松解析响应里的逐接口映射（id/endpointId、url/apifoxUrl、
  mockUrl/mockURL，以及顶层 endpoints/items/数组三种承载形态）；外层 payload
  的 endpoints 与 data.endpoints 并存时都会保留，官方响应不含该字段时形状与
  旧版一致
- 解包只在对象响应上合并外层 endpoints：数组响应（listTeams 等）保持原形状，
  不会被展开成数字键对象
- 新增 buildEndpointLinks：路由（method+path）为唯一可信主键，命中多条按
  歧义处理；operationId 仅在条目自身无路由信息且本次唯一时兜底，避免同名
  operationId 把链接串到别的接口
- 链接归因按每行实际结果区分：无映射 / 映射歧义 / 有 ID 但缺公网域名（私有
  化）/ 连项目页都推导不出。私有化部署下若 Apifox 直传了接口地址，仍按接口级
  处理；没有项目页时文案只说明这些行缺链接，不再声称"不提供任何链接"
- syncProject 结果新增 endpoints 与 endpointLinks（per-endpoint / partial /
  project + reason），进入 CLI --format json 稳定信封，部分失败的
  error.details 同样携带；dry-run 只给清单、不给任何链接
- syncToApifox 真实透出映射（此前扩展用类型断言读取，映射被静默丢弃），
  SyncOutcome 增加 endpoints 字段
- 同步报告（VS Code 面板与 CLI HTML 同源）新增「Apifox 接口」列，展示接口
  文档页/Mock 地址并逐行标注降级；表格下方显式展示降级原因；复制 TSV 与
  Markdown 带出链接、Mock 与降级标记
- 结果面板 openUrl 只放行报告内出现过的 http(s) 地址，并去掉重复分支
- 扩展同步完成通知新增「打开 Apifox 项目」入口（私有化部署不出现）
- 测试覆盖：CLI 真实 --format json 的成功/部分失败/私有化直传/dry-run/外层
  endpoints，执行 CLI 与 Webview 两套报告脚本后的单元格内容与 TSV/Markdown
  复制输出，syncToApifox 的映射透传，以及带外层 endpoints 的数组响应形状

为什么：Apifox 官方 import-openapi 只回传 counters/errors，不返回接口 ID 与
Mock 地址，因此逐接口链接在多数情况下必须走 Issue 允许的降级路径；这里把降级
原因按行归因并显式暴露，消费方不会把项目页误当成接口文档页。
